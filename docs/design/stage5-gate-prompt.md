# 5단계 설계안: ④ gate-prompt 프롬프트 인젝션 관문 (선택 단계)

- 상태: **승인 (2026-11-13), 5단계 완료**. 9장 "결정 필요" 4개 모두 추천안으로 확정. 외부 라이브러리 2개는 1주차에 추가하기 전에 관리자·다운로드 수·공개일(2주 이상)을 확인한다
- 계획서 요구:
  - 실습장에 간단한 AI 기능을 붙이고, 그 앞에서 입력·출력을 검사한다
  - AI 출력이 SQL·HTML·명령어로 바로 실행되지 않게 막는다
  - **완료 기준:** 대표적인 인젝션 공격 사례를 막고, 결과를 수치로 남긴다

## 1. 목표와 원칙

| 원칙 | 구현 방법 |
|---|---|
| **입력 필터를 믿지 않는다** | "이전 지시를 무시하라" 같은 문장 탐지는 우회가 쉽다. 입력 검사는 **기록·경고용 보조 수단**으로만 쓴다. 막는 힘은 출력 쪽 구조적 경계(2·3)에서 나온다 |
| **AI 출력은 신뢰하지 않는 입력이다** | 모델이 무엇을 내든 실행 전에 같은 검사를 거친다. 모델이 정상이든, 속았든, 가짜든 똑같이 적용된다 |
| **실행 가능한 출력은 허용 목록 방식** | SQL: 읽기 전용 단일 SELECT, 허용 테이블·열만, 사용자 범위 조건 강제. HTML: 허용 태그만 남기고 나머지는 글자로. 명령: 자유 문자열 대신 정해진 동작 ID와 인자만 |
| **AI 판단만으로 통과시키지 않는다** | 4단계와 같은 원칙. 차단 근거는 규칙 ID·위반 위치 같은 결정적 검사 결과로 남긴다 |
| 경쟁 도구와의 차이 | 범용 LLM 방화벽(예: 입력 분류 모델)과 겹치지 않게, **AI 출력이 실행되는 지점(SQL·HTML·명령)의 경계**에 집중한다. AI 코딩 도구로 만든 앱에 흔한 "모델이 만든 SQL을 그대로 실행" 패턴을 막는 라이브러리 |

## 2. 실습장에 붙일 AI 기능 (결정 1)

실습장(gate-lab)에 "주문 도우미"를 붙인다. 지금처럼 뚫린 버전과 고친 버전을 나란히 둔다.

| 기능 | 뚫린 버전 | 고친 버전 (gate-prompt 적용) | 막으려는 공격 |
|---|---|---|---|
| **자연어 주문 검색** (text-to-SQL) | 모델이 만든 SQL을 그대로 실행 | SQL 경계: 단일 SELECT, `orders` 읽기 전용 허용 열, `owner = 현재 사용자` 강제, 바인딩 | 남의 주문 조회, `DROP`·`UPDATE`, `UNION`으로 다른 테이블 읽기 |
| **상품 리뷰 요약** (HTML 표시) | 모델 출력을 HTML로 그대로 삽입 | HTML 경계: 허용 태그(`p`, `ul`, `li`, `b`, `i`)만, 속성·링크·스크립트 제거 | 리뷰 본문에 숨긴 지시(간접 인젝션) → `<script>`, `<img onerror>`, 피싱 링크 |
| **주문 처리 동작** (명령) | 모델이 고른 문자열을 명령으로 실행하는 **흉내**(실제 셸은 쓰지 않음) | 동작 경계: `cancel_order(id)`, `resend_receipt(id)`만, id는 본인 주문이어야 함 | `; rm -rf`, 남의 주문 취소, 목록에 없는 동작 |

실제 셸 실행은 실습장에서도 하지 않는다. 뚫린 버전은 "실행했다면 이렇게 됐다"를 기록만 한다(안전).

## 3. gate-prompt 모듈

```
gate-prompt/
├─ input/     입력 검사 (보조): 알려진 인젝션 표현, 역할 사칭, 숨김 문자(제로폭·양방향 제어) → 기록·경고
├─ output/    출력 경계 (핵심)
│  ├─ sql/    SQL 파서로 구조 검사 (결정 4) + 사용자 범위 조건 강제
│  ├─ html/   허용 목록 정리 (결정 4)
│  └─ action/ 동작 ID·인자 스키마 검사
├─ model/     모델 연결: 가짜 모델(기본) · Claude(선택) (결정 2)
└─ measure/   공격·정상 사례 묶음 실행 → 막음·뚫림·오탐 집계
```
- 결과는 공통 모델 `Finding`(module `PROMPT`)으로 gate-server에 저장한다

## 4. 모델 (결정 2)

- **기본: 가짜 모델(대본 모델).** 입력에 인젝션이 있으면 **일부러 따르는** 최악의 모델로 정한다
  - API 키·비용 없이 매번 같은 결과가 나온다
  - "모델이 속아도 경계가 막는지"를 보여 준다. 이것이 이 단계의 핵심 주장이다
- **선택: Claude.** 키가 있을 때만 쓴다
  - 실제 모델이 얼마나 속는지도 함께 측정한다
  - 4단계처럼 예산 장치와 호출 전 비용 확인을 둔다

## 5. 측정 (완료 기준의 "결과 수치")

| 항목 | 내용 |
|---|---|
| 공격 사례 | 직접 인젝션, 간접 인젝션(리뷰 본문·주문 메모에 숨김), SQL 밀반입, HTML·스크립트 삽입, 명령 연결, 역할 사칭, 인코딩·숨김 문자 우회. **약 40~60개**. 출처는 결정 3 |
| 정상 사례 | 정상 질문·정상 리뷰(따옴표·꺾쇠·SQL 단어가 들어간 평범한 글 포함) **약 30개**. 오탐 측정용 |
| 비교 | 뚫린 버전 / 입력 검사만 / 출력 경계만 / 둘 다 |
| 지표 | 공격별 막음·뚫림, 정상 사례 오탐(거부·내용 손상), 우회된 사례는 숨기지 않고 원인과 함께 기록 |
| 결과 | `docs/measurements/prompt-injection.md` + 원자료 JSON. CI에서 가짜 모델로 매번 다시 확인 |

## 6. 안전
- 실습장 규칙은 그대로다: 외부 공개 금지, `127.0.0.1` 바인딩, 실습장 안전 장치(`LabSafetyGuard`)도 그대로 적용한다
- 공격 사례 문서에는 실제 서비스를 겨냥한 내용을 넣지 않는다. 실습장 안에서만 의미 있는 예시만 쓴다
- 실제 셸 실행은 어떤 버전에도 넣지 않는다

## 7. 일정 (3주)
| 주차 | 할 일 |
|---|---|
| 1주 | 모듈 뼈대, 출력 경계(SQL·HTML·동작) + 단위 테스트 |
| 2주 | 실습장 주문 도우미(두 버전), 가짜 모델, 입력 검사, 통합 테스트 |
| 3주 | 공격·정상 사례 묶음, 측정·문서, CI, README |

## 8. 하지 않는 것
- 범용 프롬프트 방화벽, 입력 분류용 별도 AI 모델
- 대화 기록 저장, 다중 턴 에이전트
- 실제 명령 실행
