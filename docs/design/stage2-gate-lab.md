# 2단계 설계안: ⑤ gate-lab 취약점 실습장

- 상태: **구현 완료 (2026-11-09)**. "결정 필요" 4개 항목 모두 추천안으로 확정 (7장). 결과: [취약점 설명서](../lab/vulnerabilities.md)
- 작성일: 2026-11-09

> ⚠️ **gate-lab은 일부러 취약하게 만든 앱이다. 외부에 공개 배포하지 않는다.** 로컬(127.0.0.1)에서만 띄운다.

## 1. 목표와 역할

**목표:** 대표적인 API 취약점을 일부러 뚫어 둔 작은 앱과, 같은 기능을 고친 버전을 함께 만든다.

| 쓰임 | 내용 |
|---|---|
| 2단계 자체 | 취약점마다 "뚫린 버전에서는 공격이 통하고, 고친 버전에서는 막힌다"를 테스트로 증명 |
| 3단계 ③ gate-authz의 시험 대상 | OpenAPI 명세를 읽고 사용자 A의 토큰으로 B의 데이터를 노리는 자동 테스트가 **뚫린 버전에서는 IDOR를 찾고, 고친 버전에서는 찾지 않아야** 한다 |
| 4단계 ② gate-review의 정답지 | 취약 코드의 위치·CWE를 **코드 밖** 정답 파일에 두고 검출·오탐·미탐을 잰다 |
| 5단계 ④ gate-prompt | 간단한 AI 기능을 이 앱에 붙인다 (5단계에서 설계) |
| 데모 | 마지막 단계 시나리오 "권한 테스트로 IDOR 발견"의 무대 |

**범위 밖:** 화면(UI), 실제 결제·개인정보, 2단계 목록 밖의 취약점(필요하면 이후 단계에서 추가)

## 2. 취약점 목록 (계획서의 4종)

도메인은 작은 **주문 서비스**다: 사용자, 상품, 주문.

| # | 취약점 | 뚫린 버전 (vulnerable) | 고친 버전 (fixed) | 분류 |
|---|---|---|---|---|
| V1 | **IDOR / BOLA** | `GET·PUT·DELETE /api/orders/{id}`가 주문 주인을 확인하지 않는다. 로그인만 하면 남의 주문을 읽고 고치고 지운다 | 주인이 아니면 **404**(존재 여부도 숨김) | CWE-639, OWASP API1:2023 |
| V2 | **SQL 인젝션** | `GET /api/products/search?q=`가 검색어를 SQL 문자열에 그대로 이어 붙인다 (`UNION`으로 사용자 표 노출) | 바인딩 변수(`?`)로만 전달 | CWE-89 |
| V3 | **JWT 검증 누락** | 토큰의 payload를 Base64로 풀기만 하고 서명을 확인하지 않는다. `alg: none`도 받아들인다 → 아무나 `sub`를 바꿔 다른 사용자로 행세 | Spring Security 리소스 서버로 HS256 서명·만료 검증, 알고리즘 고정 | CWE-347, OWASP API2:2023 |
| V4 | **에러 메시지 노출** | 예외 메시지, 실행한 SQL, 스택 트레이스를 응답 본문에 그대로 돌려준다 | 일반 메시지 + 추적 ID만 응답(RFC 9457 ProblemDetail), 자세한 내용은 서버 로그에만 | CWE-209, OWASP API8:2023 |

### API (두 버전이 같은 모양)
| 메서드·경로 | 설명 | 인증 |
|---|---|---|
| `POST /api/auth/login` | 아이디·비밀번호 → JWT | 없음 |
| `GET /api/me` | 내 정보 | 필요 |
| `GET /api/orders` | 내 주문 목록 | 필요 |
| `POST /api/orders` | 주문 생성 | 필요 |
| `GET /api/orders/{id}` | 주문 하나 (V1) | 필요 |
| `PUT /api/orders/{id}` | 주문 수정 (V1) | 필요 |
| `DELETE /api/orders/{id}` | 주문 삭제 (V1) | 필요 |
| `GET /api/products/search?q=` | 상품 검색 (V2) | 없음 |
| `GET /openapi.yaml` | API 명세 (3단계 gate-authz가 읽음) | 없음 |

## 3. 구조

```
gate-lab/
├─ README.md                  # 맨 위에 경고: 외부 공개 금지
├─ Dockerfile
├─ build.gradle.kts           # Spring Boot (web, jdbc, security, oauth2-resource-server) + 결정 1의 DB
├─ src/main/java/io/gate/lab/
│  ├─ LabApplication.java     # 시작할 때 안전장치 확인 (4장)
│  ├─ common/                 # 두 버전이 함께 쓰는 것: 도메인, 저장소(정상 쿼리), 시드 데이터
│  ├─ vulnerable/             # @Profile("vulnerable"): 일부러 뚫린 구현
│  └─ fixed/                  # @Profile("fixed"): 고친 구현
├─ src/main/resources/
│  ├─ application.yml
│  ├─ openapi.yaml            # 손으로 쓴 명세 + 컨트롤러와 어긋나지 않는지 테스트
│  └─ db/schema.sql, data.sql # 가짜 사용자·상품·주문
└─ src/test/java/io/gate/lab/
   ├─ exploit/                # 취약점마다: 뚫린 버전에서 공격 성공 / 고친 버전에서 실패
   └─ ...
docs/lab/
├─ vulnerabilities.md         # 취약점 설명서: 재현 방법, 원인, 고친 방법, 분류
└─ ground-truth.json          # 4단계용 정답지: 파일·줄 범위·CWE (코드 주석에는 표시하지 않음)
```

- **한 코드베이스, 두 프로필**: 같은 앱을 `vulnerable`(127.0.0.1:8081)과 `fixed`(127.0.0.1:8082)로 띄운다. API 모양이 같아서 3단계에서 같은 명세로 두 버전을 비교할 수 있다
- **취약 코드에 "여기가 취약점" 같은 주석을 달지 않는다.** 4단계에서 AI 리뷰어가 주석을 보고 맞히면 측정이 무의미해지기 때문이다. 정답은 `docs/lab/ground-truth.json`에만 둔다

## 4. 안전장치 ("절대 외부 공개 금지")

| 장치 | 내용 |
|---|---|
| 루프백 고정 | `server.address`가 127.0.0.1·::1이 아니면 **시작을 거부**한다 (컨테이너 안에서는 compose가 호스트 127.0.0.1에만 포트를 연다) |
| 명시적 동의 | 환경 변수 `GATE_LAB_ACK=local-only`가 없으면 시작하지 않는다 |
| compose 분리 | `profiles: [lab]`. 기본 `docker compose up`으로는 뜨지 않고 `--profile lab`을 줘야 뜬다 |
| 시작 배너 | 콘솔에 "취약한 실습용 앱, 외부 노출 금지"를 크게 출력 |
| 가짜 데이터만 | 시드 데이터는 지어낸 사용자·상품뿐. 실제 개인정보 없음 |
| 문서 | `gate-lab/README.md`와 루트 README 맨 위에 경고 |
| 배포 없음 | 이미지 레지스트리에 올리지 않고, CI에서는 테스트만 하고 띄워 두지 않는다 |
| 비밀값 | JWT 서명 키는 코드에 넣지 않는다. 시작할 때마다 무작위로 만들거나 `GATE_LAB_JWT_SECRET`에서 읽는다 (결정 3) |

## 5. 테스트 계획 (완료 기준: "각 취약점 재현 + 고친 버전에서 막힘을 테스트로 증명")

| 취약점 | 뚫린 버전에서 성공해야 하는 공격 | 고친 버전 기대 결과 |
|---|---|---|
| V1 IDOR | alice 토큰으로 bob의 주문 `GET`(내용 노출)·`PUT`(값 변경)·`DELETE` | 모두 404, bob의 주문은 그대로 |
| V2 SQLi | `q=' UNION SELECT username, password_hash, ... FROM users--`로 사용자 표 노출, `q='`로 오류 유발 | 검색어로 그대로 취급되어 결과 0건, 오류 없음 |
| V3 JWT | ① 서명 없는 `alg:none` 토큰 ② 다른 키로 서명한 토큰 ③ 만료된 토큰으로 `GET /api/me` → 위조한 사용자로 응답 | 모두 401 |
| V4 에러 노출 | 잘못된 입력·V2 오류에서 응답 본문에 `SQL`, 예외 클래스 이름, 스택 트레이스 포함 | 일반 메시지 + 추적 ID만, 내부 정보 없음 |
| 공통 | 정상 사용 흐름(로그인 → 내 주문 CRUD)은 **두 버전 모두** 동작 | 같음 |
| 명세 | `openapi.yaml`의 경로·메서드가 실제 컨트롤러와 일치 | 같음 |
| 안전장치 | 루프백이 아닌 주소, `GATE_LAB_ACK` 없음 → 시작 거부 | 같음 |

- 테스트는 실제 HTTP로 앱을 띄워(랜덤 포트) 공격 요청을 보낸다
- 결과를 표로 모은 **재현 보고서**(`docs/lab/vulnerabilities.md`)를 함께 만든다

## 6. 일정 (2주)

| 주차 | 할 일 |
|---|---|
| 1주 | 모듈 뼈대, 안전장치, 시드 데이터, 로그인과 V3(JWT) 두 버전, V1(IDOR) 두 버전, 공격 테스트 |

## 7. 확정된 결정 (2026-11-09)
| # | 항목 | 결정 | 이유 |
|---|---|---|---|
| 1 | DB | **H2 메모리 DB** (PostgreSQL 호환 모드) | gate-server DB와 완전히 분리되고, Docker 없는 PC에서도 공격 테스트가 바로 돈다. 띄울 때마다 초기화 |
| 2 | 뚫린·고친 버전 구조 | **한 앱 + 프로필 2개** (`vulnerable` 8081, `fixed` 8082) | API 모양이 같아 3단계에서 같은 명세로 비교. 취약·수정 코드가 패키지로 나뉘어 나란히 비교 |
| 3 | 데모 계정 비밀번호 | **시작할 때 무작위 생성**, 콘솔에만 출력. `GATE_LAB_DEMO_PASSWORD`로 지정 가능 | 코드·문서·커밋에 비밀번호를 남기지 않는 규칙과 일치. 테스트·3단계 도구는 환경 변수로 지정 |
| 4 | OpenAPI 명세 | **손으로 쓴 `openapi.yaml` + 일치 테스트** | 외부 라이브러리 추가 없음. 컨트롤러와 어긋나면 테스트 실패 |
