# 설계안: 상업적 사용 유료화(라이선스)와 사용 확인

- 상태: **승인·구현 완료 (2026-11-17)**. 6장 결정 확정: 1~3은 추천안, 4는 GitHub 이슈, 5는 추천안(따로 묻지 않고 기본값으로 정함, 바꾸려면 구현 전에 말하면 됨)
- 요청: 개인·비상업적 사용은 무료, 기업의 상업적 사용은 유료. 상업적으로 쓰는지 확인하는 장치

## 1. 원칙

| 원칙 | 내용 |
|---|---|
| 판단 기준은 라이선스 조건 | "상업적 목적인지"는 프로그램이 정확히 알 수 없다(회사 PC에서 공부, 집에서 회사 일). 사용 조건은 LICENSE가 정하고, 프로그램은 **라이선스 키 확인**과 **사용자가 동의한 정보**만 다룬다 |
| 숨긴 전송 금지 | GATE는 "몰래 데이터를 보내는 패키지를 막는 도구"다. 알리지 않은 전송·추적은 넣지 않는다(이 프로젝트가 막으려는 문제를 스스로 만들지 않는다) |
| 비상업 사용자는 불편 없이 | 키가 없어도 모든 기능이 동작한다(결정 2에 따라 바뀔 수 있음). 안내 문구만 보인다 |
| 비밀값은 저장소 밖 | 라이선스 서명 개인 키는 저장소·문서·커밋에 넣지 않는다. 코드에는 공개 키만 |

## 2. 라이선스 (결정 1)

| 후보 | 상업적 사용 | 비상업적 사용 | 장점 | 단점 |
|---|---|---|---|---|
| **PolyForm Noncommercial 1.0.0** (추천) | 별도 상업 라이선스 필요 | 무료 | 요청과 정확히 맞음. 짧고 읽기 쉬운 표준 문서. 개인·교육·비영리 단체 사용 허용이 명확 | "오픈소스"(OSI 기준)가 아님. 외부 기여가 줄 수 있음 |
| Business Source License 1.1 | 운영 환경 사용은 유료(조건을 직접 정함) | 무료 | 정한 기간(최대 4년)이 지나면 오픈소스로 바뀌어 신뢰를 얻기 쉬움 | 허용 범위(Additional Use Grant)를 직접 써야 해서 모호해지기 쉬움 |
| AGPL-3.0 + 상업 라이선스 | 소스를 공개하면 무료, 공개하기 싫으면 유료 | 무료 | 진짜 오픈소스 | **회사가 소스 공개 조건을 지키면 돈을 낼 필요가 없음** → 요청("기업은 유료")과 다름 |

- 사용하는 외부 라이브러리(Apache-2.0·MIT·BSD 등)는 어느 후보와도 함께 쓸 수 있다. 각 라이브러리는 자기 라이선스를 그대로 따른다
- 바꾸는 파일: `LICENSE`(교체), `COMMERCIAL.md`(새로: 상업 라이선스가 필요한 경우·문의 방법), README 영·한 "라이선스" 절, `dashboard/package.json`의 `license` 표기, `docs/progress.md`의 0단계 결정 기록(바뀐 사실 추가)

## 3. 라이선스 키 (상업 사용자용)

```
키 = base64url(내용 JSON) + "." + base64url(Ed25519 서명)
내용: { "id", "licensee"(회사명), "seats", "issuedAt", "expiresAt", "modules" }
```
- **오프라인 검증:** 공개 키만 `gate-common`에 넣는다. 네트워크 없이 검증하므로 키 확인 때문에 데이터가 나가지 않는다
- 키를 읽는 곳: 환경 변수 `GATE_LICENSE_KEY` 또는 파일 `~/.gate/license.key`
- 검증 결과: `VALID`(회사명·만료일) · `EXPIRED` · `INVALID`(위조·형식 오류) · `NONE`
- 표시 위치:
  - CLI 4종(gate-pkg·gate-authz·gate-review·gate-prompt): 오류 출력(stderr)에 한 줄. JSON 출력과 종료 코드는 바꾸지 않는다(CI·훅 동작 유지)
  - gate-server: 시작 로그, 대시보드 아래쪽에 라이선스 상태
  - Claude Code 훅: 표시하지 않는다(설치 명령마다 나오면 방해가 되므로)
- **키 발급 도구:** `gate-license` 명령(결정 5). 개인 키 파일 경로를 받아 키를 만든다. 개인 키는 저장소 밖에 둔다
- 키가 없거나 만료된 경우의 처리는 결정 2

## 4. 사용 정보 보내기 (결정 3)

추천: **opt-in(사용자가 켜야만 보냄)**. 아래 원칙으로 한정한다.
- 기본값은 꺼짐. `gate telemetry on`처럼 명시적으로 켜야 하고, 켜기 전에 보낼 내용 예시를 그대로 보여 준다
- **보내는 것:** 설치 ID(처음 켤 때 만든 무작위 UUID), GATE 버전, 모듈 이름, 하루 실행 횟수, 라이선스 키 ID(있으면), 라이선스 상태
- **보내지 않는 것:** 코드, 파일 경로, 패키지 이름·목록, 검사 결과, 사용자명, 호스트명, 저장소 주소, 회사를 알아내기 위한 IP 조회
- 받는 주소는 설정값(`GATE_TELEMETRY_URL`)이다. 코드·문서에 실제 서버 주소를 넣지 않는다. **받는 서버는 이번 범위가 아니다**
- 수집 항목·보관 기간·끄는 방법을 `PRIVACY.md`에 적는다
- 이 방식으로 알 수 있는 것은 "켠 사람들의 사용량"뿐이다. **키 없이 몰래 쓰는 회사를 찾아내는 장치는 아니다.** 그 확인은 라이선스 조건과 키로 한다

## 5. 테스트
- 키: 정상·위조(내용 한 글자 변경)·만료·다른 공개 키로 서명·형식 오류
- 사용 정보:
  - 켜기 전에는 네트워크 요청 0건 (가짜 서버로 확인)
  - 켠 뒤에는 보내는 본문에 금지 항목이 없음 (경로·호스트명·사용자명 문자열 검사)
  - 끄면 다시 0건
- CLI: 키가 있든 없든 JSON 출력·종료 코드가 같음 (기존 CI·훅 계약 유지)
