# 마지막 단계(★) 설계안: 대시보드·데모·정리

- 상태: **승인 (2026-11-15), 1·2주차 완료**. 8장의 결정 4개 확정 (2개는 추천안과 다르게 결정: 차트·UI 키트 사용, CI 자동 캡처)
- 계획서 요구:
  - 모든 모듈의 검사 결과를 한 화면에서 본다 (React)
  - 데모 시나리오: "AI가 가짜 패키지 추천 → 검문소 차단 → 취약 코드 PR 리뷰 → 권한 테스트로 IDOR 발견"
  - README에 문제 정의, 측정 결과, 데모 영상(또는 화면)을 정리한다

## 1. 지금 상태와 빈 곳

| 모듈 | gate-server 저장 | 비고 |
|---|---|---|
| ① gate-pkg | 있음 (`GATE_SERVER_URL`) | 훅·Action·CLI |
| ② gate-review | **없음** | 결과는 PR 댓글·JSON 출력뿐 → 1주차에 추가 |
| ③ gate-authz | 있음 | CI에서 PostgreSQL 저장 확인 |
| ④ gate-prompt | 있음 | CI에서 PostgreSQL 저장 확인 |
| gate-server | 저장 API(`POST /api/scan-runs`)만 있다 | **조회 API가 없음** → 1주차에 추가 |

## 2. 원칙

| 원칙 | 구현 방법 |
|---|---|
| **결과에 든 글은 데이터다** | 근거(evidence)에는 공격 문자열이 그대로 들어 있다(프롬프트 인젝션 사례, 악성 패키지 설치 스크립트 조각, 취약 코드). 화면은 모든 글을 React 기본 이스케이프로만 표시하고, `dangerouslySetInnerHTML`은 쓰지 않는다. **CSP**(`default-src 'self'`, 인라인 스크립트 금지)와 `X-Content-Type-Options: nosniff`를 붙인다 |
| 읽기 전용 | 화면은 결과를 보기만 한다. 결과를 지우거나 판정을 바꾸는 기능은 넣지 않는다 |
| 공급망 최소화 | 이 프로젝트는 "AI가 추천한 패키지를 확인 없이 설치하는 문제"를 막는 도구다. 프론트 의존성은 최소로 하고, **추가할 때마다 gate-pkg로 직접 검사**해 그 결과를 기록한다(제품을 스스로 써 보는 사례) |
| 버전 고정 | `package-lock.json`으로 고정하고 `npm ci`로만 설치한다. Node 빌드 이미지는 태그 + digest로 고정한다 |
| 외부 공개 금지 유지 | gate-server는 지금처럼 `127.0.0.1`에만 연다 |

## 3. gate-server 조회 API (1주차)

| API | 내용 |
|---|---|
| `GET /api/summary` | 모듈별 마지막 실행, 판정별(BLOCK·WARN·PASS)·심각도별 개수, 전체 실행 수 |
| `GET /api/scan-runs?module=&limit=` | 최근 실행 목록 (실행마다 판정별 개수) |
| `GET /api/scan-runs/{id}` | 실행 하나와 그 결과 전체 |
| `GET /api/findings?module=&decision=&severity=&limit=&before=` | 최근 결과 목록 (필터, 시각 기준 페이지 나누기) |

- 목록 상한은 200개다. 잘못된 필터 값은 400으로 막는다.
- 모든 질의는 바인딩 변수만 쓴다.
- 테스트: Testcontainers(PostgreSQL) 통합 테스트로 한다. 로컬에는 Docker가 없으므로 CI에서 돌리고, 건너뛰면 실패로 처리한다.

## 4. 화면 (2주차)

| 화면 | 내용 |
|---|---|
| **개요** | 모듈 4개 카드(마지막 실행 시각, BLOCK·WARN 수), 판정·심각도 막대, 최근 BLOCK 10개 |
| **결과 목록** | 모듈·판정·심각도 필터. 표: 시각 · 모듈 · 판정 · 규칙 · 위치(패키지·파일:줄·엔드포인트) · 제목 |
| **결과 상세** | 위치, 근거(키-값 표, 긴 글은 접기), 출처(RULE·AI·RULE_AND_AI), 같은 지문(fingerprint)의 이전 기록 |

- 빌드 결과물(`dist`)은 gate-server가 함께 제공한다(결정 1). 같은 주소라서 CORS 설정이 필요 없다.
- 차트·UI 키트를 쓴다(결정 2). 구체 라이브러리는 2주차에 후보 2~3개를 **gate-pkg로 검사**하고(관리자·다운로드 수·공개일·설치 스크립트·알려진 취약점) 확인받은 뒤 추가한다.
- 프론트 테스트는 화면 구성 요소 몇 개만 한다. 특히 "근거에 든 `<script>`가 글자로 보이는지"를 확인한다.

## 5. 데모 시나리오 (3주차)

`scripts/demo.sh` (compose로 db·server·실습장을 띄운 뒤 차례로 실행, 모든 결과를 gate-server에 저장):

| 순서 | 장면 | 실행 | 기대 결과 |
|---|---|---|---|
| 1 | AI가 존재하지 않는 패키지를 추천해 설치하려 함 | Claude Code 훅 입력을 흉내 낸 `npm install <지어낸 이름>` → gate-pkg 훅 | 차단(deny) + 이유 |
| 2 | AI가 만든 코드 PR에 SQL 인젝션 | 데모 브랜치 변경분 → gate-review(키 없으면 정적 분석만) | BLOCK, 파일·줄·규칙 |
| 3 | 배포 전 권한 검사 | gate-authz → 실습장 뚫린 버전 | IDOR(조회·수정·삭제) 발견 |
| 4 | AI 기능의 프롬프트 인젝션 | gate-prompt measure | 출력 관문 46/46 |
| 5 | 한 화면에서 확인 | 대시보드 | 모듈 4개의 결과가 모두 보임 |

- CI의 compose-smoke 잡이 이 스크립트를 실행하고, `GET /api/summary`에 모듈 4개가 모두 있는지 확인한다.
- 화면 캡처는 CI에서 자동으로 한다(결정 4). Playwright(공식 Microsoft 패키지, 버전 고정, gate-pkg로 검사)로 대시보드 화면을 캡처한다. 화면이 비었거나 오류가 보이면 CI를 실패시키고, 캡처는 아티팩트로 올린다.
- GitHub 아티팩트를 내려받으려면 로그인이 필요하다. 그래서 README에 넣을 이미지는 같은 캡처 스크립트를 이 PC에서도 실행해 만든다.
